# GeneratePicture Auto-Optimized Rendering — Implementation Summary

## Objective

Complete [`generate-picture-auto-dither-plan.md`](generate-picture-auto-dither-plan.md): replace the production firmware-style ditherer with a pure-Rust reproduction of the offline web editor's default `GeneratePicture.js` flow after **Auto-Optimieren**, while preserving queue safety, static frame serving, and room for future palette/exposure/contrast/saturation controls.

## Prompt-to-artifact checklist

| Requirement | Concrete evidence |
|---|---|
| Discard old production ditherer | `src/renderer.rs` no longer contains or calls `firmware_dither`, clean-color snapping, firmware integer buffers, RGB565 reduction, staged firmware resize, or stretch-to-fill. The obsolete `firmware-profile-v1.json` fixture is removed. |
| Use the epdoptimize Rust path | `src/epd_pipeline.rs` performs calibrated-palette quantization/error diffusion with RGB/LAB dispatch and hardware-index mapping. `src/dither.rs` retains exact pinned epdoptimize diffusion semantics and all scoped kernels. `ServerDitherBmp`, preview, enqueue, refill, orientation rerender, and queue-wide rerender all converge through `renderer::render`. |
| Match GeneratePicture defaults | `src/epd_profile.rs::generate_picture_auto_v2` fixes the exact `spectra6Custom` colors, indices `0,6,1,2,3,5`, natural auto intent, selected Floyd–Steinberg override, serpentine scan, zero manual adjustments, aspect-fit placement, and browser-like resize policy. Unit tests snapshot these values. |

## Safety audit

The new modules operate only on in-memory image buffers. Persistent writes remain confined to the existing settings and queue stores. Source suppliers/catalogs remain read-only. Queue derivatives still validate format, digest, dimensions, target, and profile before serving. Queue-wide rerender publishes unique replacement objects and the descriptor transactionally; profile migration does not alter source objects or supplier history.
