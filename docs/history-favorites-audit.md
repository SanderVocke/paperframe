## Storage/mutation inventory and implementation adjustment

- Current transitions: raw enqueue, rendered batch/front/back enqueue, reorder, remove, advance/drop/rotate and migration seed invoke `capture_current`. Same-ID source preservation, orientation/text/edit and global rerender do not promote. Startup legacy-current import uses enqueue. Reads and frame delivery never independently capture.
- Mutable queue derivative replacement/thumbnail invalidation and queue remove/advance deletion retain queue-only ownership. Saved snapshots copy to separate opaque `saved-*` assets; explicit saved thumbnail names are independent of queue IDs. This intentionally uses more disk than cross-collection object sharing. It achieves the requested lifetime invariant without making each queue deletion retain a shared file. Startup rejects queue entries that claim the saved namespace and validates saved ownership.
- Saved deletion is reachability-based: history/favorites reference picture IDs; `prune_pictures` removes unused records; `cleanup_saved` removes only unreachable saved files under the mutation lock. Startup orphan cleanup includes queue and saved assets. Enqueue/import rollback removes only newly published files; failed snapshot/descriptor operations clean saved orphans against the live descriptor.
- Publication functions to audit: `publish_enqueue_batch`, `publish_rendered_batch`, `publish_rerender`, `replace_derivative`, `persist_descriptor`, `write_cached_thumbnail`; mutations/cleanup: `preserve_legacy_source`, `remove`, `advance_internal`, `rerender_all`, `set_orientation`, `set_text`, `edit_entry`, `retain_picture`, `cleanup_saved`, `initialize`.
- A real test rerun exposed a current-selection/deletion race; `current` now pins selection and byte preparation with the mutation lock.
